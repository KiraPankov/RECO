# Ограничения решения

## Поддерживаемые условия

- **Устройства:** Android 8.0+ (API 26), arm64-v8a. Для эмулятора — x86_64. Это совпадает с архитектурами, для которых собраны sherpa-onnx и LiteRT-LM.
- **Языки:** основной русский, также английский. Parakeet v3 поддерживает 25 европейских языков, переключение языка внутри разговора допускается.
- **Форматы:** всё, что декодирует Android — mp3, m4a/aac, ogg/opus, wav, flac, amr, звуковая дорожка mp4.
- **Длина записи:** до 3 часов.
- **Число говорящих:** определяется автоматически. Проверено на 4 участниках.

## Известные ограничения

- **Размер.** APK 1,1 ГБ, на устройстве нужно около 2,5 ГБ свободного места: при первом запуске модели копируются во внутреннюю память, потому что библиотекам нужны пути к файлам.
- **Одновременная речь** нескольких участников относится к одному из говорящих. Перекрытия не разделяются.
- **На сильно зашумлённой записи (SNR 5 дБ)** растёт WER: 10,3% против 0,9% на чистой. Диаризация 99,0%. Граница реплик ставится посередине паузы, поэтому ошибка конца реплики больше, чем на чистой записи: ~0,2 с.
- **Перебивание без паузы.** Если участник начинает говорить вплотную к концу чужой фразы, граница между ними берётся от pyannote. Паузу VAD здесь найти нельзя.
- **LLM на устройстве проверена на эмуляторе** (Android Studio, API 37, запись `clean.wav`, см. [видео](../artifacts/demo/README.md)): модель запускается и обрабатывает все фрагменты. На этой записи все 7 её ответов отброшены проверкой слов — Qwen3-0.6B пыталась менять слова. В расшифровке остаётся пунктуация распознавателя. Тесты в GitHub Actions на 900 фразах open_stt и тестовых диалогах дают ту же картину: отклоняется 84–93% ответов LLM, WER до и после LLM совпадает (см. [TEST_RESULTS.md](TEST_RESULTS.md)).
- **LLM может ничего не улучшить.** Parakeet уже ставит пунктуацию. Проверка слов гарантирует, что LLM не ухудшит WER, но не гарантирует, что она улучшит пунктуацию: это показывают тесты.
- **Скорость на реальном телефоне не замерена.** На эмуляторе Android на ПК — RTF 1,28 (54 с записи за ~1 мин, с LLM). Как это соотносится со скоростью на телефоне, не проверялось.
  - На ПК (2 ядра) RTF ≈ 0,23 без LLM.
  - По данным сообщества, Qwen3-0.6B на процессоре флагманского телефона генерирует около 47 токенов/с.
  - Время обработки каждой записи показывается на экране расшифровки («обработка … RTF …»).
- **Память.** Модели загружаются по очереди. Пик ожидается при работе LLM: около 1 ГБ по данным сообщества, на устройстве не замерялось. Рекомендуется телефон с 6+ ГБ ОЗУ (оценка, не замер).
- **Отмена во время этапа «Определение говорящих»** срабатывает только после его окончания: движок не поддерживает прерывание изнутри.
- **Тестовые диалоги синтетические** (TTS-голоса). Вручную размеченные наборы open_stt — настоящая речь, но в каждой записи один говорящий, поэтому диаризацию на них не проверить.
- **Подпись APK.** APK из GitHub Actions подписан временным debug-ключом, своим для каждой сборки. Чтобы поставить новую версию поверх старой, старую нужно удалить.

## Что не входит в текущую версию

- Разделение одновременной речи.
- Шумоподавление: в тестах ухудшало результат.
- Аппаратное ускорение (NNAPI / GPU): используется CPU, до 4 потоков.

## Риски демонстрации

- **Первый запуск.** Распаковка ~1 ГБ моделей занимает до минуты-двух. Перед демонстрацией стоит один раз открыть приложение и дождаться, пока исчезнет карточка «Подготовка моделей».
- **Нехватка памяти.** На телефоне с малым объёмом ОЗУ при загрузке моделей возможна нехватка памяти. Приложение покажет ошибку в карточке задачи. Если не запустится только LLM, расшифровка всё равно будет готова.
- **Архитектура.** На 32-битных устройствах APK не установится.

## Дальнейшее развитие

- Замер и оптимизация RTF на устройстве: GPU-бэкенд LiteRT-LM, подбор числа потоков.
- Разделение перекрывающейся речи.
- Подбор порога кластеризации на реальных многоголосых записях.
