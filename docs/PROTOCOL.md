# Протокол обработки и формат вывода

## Цели

- Преобразовать аудиозапись разговора в структурированную расшифровку полностью на устройстве, без интернета.
- Для каждой реплики определить говорящего, время начала и конца, текст.
- Выдать результат в формате JSON, заданном организаторами.

## Входные данные

| Параметр | Значение |
|---|---|
| Источник | файл из памяти устройства (системный выбор файла) или запись в приложении |
| Форматы | mp3, m4a/aac, ogg/opus, wav, flac, amr, звуковая дорожка mp4 — всё, что декодирует MediaCodec |
| Частота и каналы | любые; приводятся к 16 кГц моно с антиалиасинговым фильтром |

## Формат вывода

Корневой объект содержит массив `transcript`. Реплики отсортированы по `start_ms`.

| Поле | Тип | Описание |
|---|---|---|
| `transcript` | array | массив реплик |
| `speaker_id` | string | `speaker_1`, `speaker_2`, … — в порядке первого появления в записи |
| `start_ms` | integer | начало реплики, мс от начала записи |
| `end_ms` | integer | конец реплики, мс; всегда больше `start_ms` |
| `text` | string | текст реплики с пунктуацией |

Кодировка UTF-8. Файл сохраняется только по явному действию пользователя, в выбранное им место.

## Этапы обработки

1. **Декодирование** → PCM 16 кГц моно.
2. **Предобработка** → удаление постоянной составляющей, нормализация громкости.
3. **Диаризация** → сегменты с меткой говорящего (pyannote segmentation 3.0 + CAM++ + кластеризация).
4. **Разрез по паузам** → сегменты режутся по паузам, найденным Silero VAD.
5. **Уточнение говорящих** → второй проход по эмбеддингам голоса.
6. **Нарезка** → куски до 28 с, склейка соседних кусков одного говорящего.
7. **Распознавание** → Parakeet TDT 0.6B v3.
8. **Пунктуация LLM** → Qwen3-0.6B; ответ принимается, только если слова не изменились.
9. **Сборка реплик** → нумерация говорящих, объединение соседних реплик одного говорящего, сохранение.

Модели загружаются по очереди и освобождаются после своего этапа. Подробности и пороги — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Временные метки

- Отсчитываются от начала исходного файла, в миллисекундах.
- Границы берутся из сегментов диаризации и уточняются по паузам Silero VAD.
- Метки отдельных слов не выводятся.

## Ошибки и восстановление

| Ситуация | Поведение |
|---|---|
| Файл не удалось декодировать | сообщение пользователю, обработка не начинается |
| В записи нет речи | пустой массив `transcript` |
| LLM не запустилась на устройстве | расшифровка готова с пунктуацией распознавателя |
| LLM изменила слова | ответ LLM отбрасывается, остаётся текст распознавателя |
| Приложение свёрнуто | обработка продолжается в foreground-сервисе |
| Ошибка в реплике | реплику можно исправить вручную или обработать фрагмент повторно |

## Совместимость

- Android 8.0+ (minSdk 26), arm64-v8a; для эмулятора — x86_64.
- Около 2,5 ГБ свободного места: модели распаковываются во внутреннюю память при первом запуске.
- Разрешения `INTERNET` нет; используются микрофон, уведомления и foreground-сервис.

## Пример

```json
{
  "transcript": [
    { "speaker_id": "speaker_1", "start_ms": 31, "end_ms": 6055, "text": "Добрый день! Давайте начнем совещание." },
    { "speaker_id": "speaker_2", "start_ms": 6420, "end_ms": 9310, "text": "Добрый день. Первый вопрос — сроки." }
  ]
}
```
