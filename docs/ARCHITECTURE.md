# Архитектура решения

## Контекст

Пользователь импортирует аудиофайл из памяти устройства или записывает разговор в приложении. Приложение строит расшифровку диалога: кто говорил, когда (начало и конец в миллисекундах) и что. Результат можно просмотреть, прослушать, исправить и экспортировать в JSON.

Все модели встроены в APK, все вычисления выполняются на устройстве. Разрешения `INTERNET` в манифесте нет.

## Конвейер обработки

```
аудио ─► 16 кГц моно ─► предобработка ─► диаризация ─────────► разрез    ─► уточнение ─► нарезка ─► Parakeet ─► LLM: пунктуация ─► реплики
         (MediaCodec)   (без DC,         (pyannote + CAM++     по паузам    спикеров      ≤ 28 с     (речь →     + проверка слов      speaker,
                         громкость)        + кластеризация)    (Silero VAD) (2-й проход)  по паузам   текст)                          start, end, text
```

| Этап | Как работает |
|---|---|
| Декодирование | MediaExtractor + MediaCodec; любой формат Android в 16 кГц моно; ресемплер с антиалиасинговым фильтром |
| Предобработка | Вычитание скользящего среднего (0,1 с) убирает постоянную составляющую. Нормализация: 99,9-й перцентиль амплитуды → 0,9, усиление не больше ×30 |
| Диаризация | sherpa-onnx: pyannote segmentation 3.0 находит участки речи и смены говорящих. 3D-Speaker CAM++ строит эмбеддинг («отпечаток») голоса. Кластеризация с порогом 0,7, число говорящих определяется автоматически |
| Разрез по паузам | На шумной записи pyannote склеивает соседние реплики разных людей в один сегмент, и конец реплики достаётся следующему говорящему. Детектор речи Silero VAD (порог 0,7, пауза от 0,2 с) находит паузы между фразами. Каждый сегмент режется посередине каждой паузы внутри него. Границы диаризации без паузы (перебивание) сохраняются. Кусок короче 1 с, примыкающий к соседу без паузы, получает метку соседа |
| Уточнение спикеров | pyannote работает окнами по 10 с и путает метки соседних реплик. Для каждого куска ≥ 0,5 с заново считается отпечаток. По кускам ≥ 1 с строятся центроиды спикеров, похожие центроиды (косинус > 0,75) объединяются, и каждый кусок переназначается ближайшему спикеру до сходимости. Кусок короче 1 с сохраняет метку, если у неё есть центроид; если его спикер встречается только в коротких кусках, кусок отдаётся ближайшему спикеру |
| Нарезка | Обрезка перекрытий; отбрасывание кусков < 0,3 с; склейка кусков одного спикера с паузой < 0,8 с; разрез кусков > 28 с в самой тихой точке |
| Распознавание | NVIDIA Parakeet TDT 0.6B v3 (int8). Сам ставит базовую пунктуацию |
| Пунктуация LLM | Qwen3-0.6B (int4, LiteRT-LM) правит знаки препинания и заглавные буквы в каждом куске. Подробности ниже |
| Сборка реплик | Спикеры нумеруются по порядку появления; соседние реплики одного спикера с паузой < 1,5 с объединяются |

Модели загружаются по очереди и освобождаются сразу после своего этапа: диаризация → Parakeet → LLM. Задачи выполняются строго последовательно.

## Локальная LLM: только пунктуация, слова не меняются

За точность расшифровки (WER) дают 40 баллов. Если LLM поменяет хоть одно слово, WER вырастет. Поэтому LLM поручены только знаки препинания и заглавные буквы, и её ответ проходит жёсткую проверку (`PunctuationGuard`):

1. Из ответа убираются служебные части: блок `<think>`, кавычки вокруг всего ответа, лишние пробелы.
2. Обе строки разбиваются на слова: нижний регистр, знаки по краям слов отбрасываются.
3. Если последовательности слов не совпадают в точности, ответ отбрасывается и остаётся текст распознавателя. Это касается:
   - замены, вставки, удаления или перестановки слова;
   - замены «е» на «ё»;
   - цифр, записанных словами (и наоборот);
   - нового дефиса внутри слова;
   - пояснения перед ответом.

Параметры LLM:
- Жадное декодирование (topK = 1, temperature = 0) — результат воспроизводим.
- Каждый кусок обрабатывается в отдельном разговоре, без истории.
- Промпт и шаблон чата (ChatML без режима размышлений) — в `app/src/main/assets/llm/`.
- Модель собрана с KV-кэшем на 1280 токенов. Куски длиннее 600 символов в LLM не отправляются.

Если LLM не запустится на устройстве (например, процессор не поддерживается), расшифровка всё равно будет готова: останется пунктуация распознавателя. На экране расшифровки видно, сколько фрагментов LLM исправила и сколько её ответов отброшено.

Проверка слов реализована дважды: в Kotlin (приложение) и в Python (тесты). Обе реализации сверяются на одних и тех же 20 примерах (`app/src/test/resources/punctuation_guard_cases.json`). Тест на open_stt дополнительно проверяет, что WER до и после LLM в точности совпадает.

## Компоненты приложения

| Пакет | Ответственность |
|---|---|
| `audio` | `AudioDecoder` (в том числе фрагмент по времени), `Resampler`, `Preprocessor`, `AudioImporter` |
| `engine` | `TranscriptionEngine` — конвейер; `PauseSplitter` — разрез сегментов по паузам VAD; `SpeakerRefiner` — второй проход диаризации; `Segments` — логика сегментов; `LlmPunctuator` — LLM; `PunctuationGuard` — проверка слов |
| `ui` | Экраны на Jetpack Compose в стиле «ретро-рабочий стол»: окна с обводкой и жёсткой тенью, моноширинный шрифт IBM Plex Mono, палитра из иконки. Общие элементы — `ui/components`, цвета и шрифты — `ui/theme` (светлая и тёмная темы) |
| `models` | `ModelStore`: копирует модели из assets во внутреннюю память при первом запуске и после обновления APK, проверяет размеры по манифесту |
| `work` | `JobManager` — очередь, прогресс, замер времени (RTF); `WorkService` — foreground-сервис, чтобы обработка шла при свёрнутом приложении |
| `record` | Запись с микрофона (AAC/m4a) с индикатором уровня |
| `data` | Модель расшифровки и хранение в JSON |
| `export` | Экспорт в формате задания |
| `ui` | Экраны Compose: список и запись, расшифровка с плеером и правкой |

## Сборка и поставка

- Gradle-задача `fetchModels` скачивает модели в `app/models-assets/models` и пишет манифест (пути и размеры). Каталог подключается к APK как assets, без сжатия.
- GitHub Actions (`.github/workflows/android.yml`) собирает APK и при теге `v*` публикует его в Releases: файлы больше 100 МБ в репозиторий не загрузить. Модели кэшируются между сборками.
- Тесты качества (`.github/workflows/eval.yml`) берут ровно те файлы моделей, что попадают в APK. Конвейер на Python повторяет приложение: sherpa-onnx 2.0.1 и LiteRT-LM 0.19.1, тот же промпт, шаблон и проверка слов.

## Безопасность и приватность

- Разрешения `INTERNET` в манифесте нет: аудио и текст физически не могут уйти с устройства.
- Записи, расшифровки и модели хранятся во внутренней памяти приложения, резервное копирование отключено (`allowBackup=false`).
- Экспорт выполняется только по явному действию пользователя, в выбранный им файл (Storage Access Framework).
- Разрешения: микрофон (только для записи), уведомления (прогресс), foreground-сервисы (обработка и запись в фоне).
